## Verdict

Autorotate is **two products at different maturities wearing one name.**
`AutorotateCore` and the Apple apps are careful, well-documented engineering —
dependency-injected, actor-isolated, with guards that show someone thought
hard about what happens when a rotation half-fails.  The web control center
and the Android companion are demonstrations dressed as production software.

Three findings make this more than a punch list:

1. The web API has **no authentication of any kind** — not weak auth, none.
2. A connector with no stored credentials **silently mints a fake secret and
   writes it to live targets**, verifies it against itself, and reports
   success.
3. Android's rotation **does nothing at all** while writing audit records
   claiming the full six-stage pipeline ran.

Each inverts the product's core promise.

A fourth arrived while this review was being written: #63 committed a
**debug-signed release APK** to the public repo (AR-33), signed with a key
whose private half ships with every Android SDK — so anyone can forge an
update-compatible build of a secrets manager.  Everything else in this report
is ordinary engineering debt and can wait.  These cannot.

## Critical

### AR-01 — The web control center has no authentication whatsoever

`middleware.ts` exports exactly one procedure builder — `publicQuery =
t.procedure` — and all 40-odd procedures use it.  The tRPC context carries
only `req` and `resHeaders`: no session, no cookie parsing, no token check.
`Login.tsx` is a placeholder whose only control links to `/dashboard`, and
console routes sit behind `AppShell`, which renders `<Outlet/>` with no guard.

Anyone reaching the deployment can enumerate secrets, register connectors,
trigger `secrets.rotateNow` against live credentials, delete the inventory,
and read the audit log.  Worst: they can attach a webhook target with
`includeValue: true` pointed at a server they control, turning the
zero-plaintext engine into a plaintext exfiltration pipeline.

- `apps/web/api/middleware.ts:10`
- `apps/web/api/context.ts:3`
- `apps/web/src/pages/Login.tsx:11`
- `apps/web/src/App.tsx:23`

### AR-02 — A connector with no credentials mints a fake secret and writes it to live targets

`ServerConnector.rotate()` falls back to demo generation on
`isDemoMode() || !config`.  The engine uses `result.value` unconditionally —
`result.demo` only prefixes the step *message*.  `pushToTarget` gates on
`isDemoMode()` alone, so in real mode it performs a genuine Infisical upsert.

1. Import a `.env`.  `importBatch` auto-creates connectors with
   `status: "connected"` and no `configEnc`.
2. `decryptJson(null)` → `null`, so `rotate(null)` hits `!config` and returns
   a random `sk_live_…`.
3. PUSH runs for real — the fake value is written to production Infisical.
4. VERIFY reads it back and compares it to itself.  It matches.
5. COMMIT sets `status: "healthy"`, `version + 1`.  The old value is gone;
   Autorotate never kept it.

Steps 2–3 confirmed by executing the shipped code with `AUTOROTATE_DEMO=0`:
`getConnector("stripe").rotate(null)` returns a different realistic
`sk_live_…` on every call, with `demo: true` and a populated `value`.  Same
path for Cloudflare, OpenAI, Twilio and every other connector.

- `apps/web/api/autorotate/connectors.ts:502`
- `apps/web/api/autorotate/engine.ts:378`, `:196`
- `apps/web/api/routers/autorotate.ts:386`

### AR-03 — Demo mode is the default

`isDemoMode()` returns `true` when `AUTOROTATE_DEMO` is unset or empty.  A
production deploy that forgets one variable simulates every rotation, marks
every secret `healthy`, increments versions, and writes audit entries that
read as real commits — while credentials silently age past policy forever.

File targets are the exception ("always execute for real"), so demo mode
still overwrites real `.env` files with generated values.  Safe defaults for
a security tool fail closed and require an explicit opt-in to simulate.

- `apps/web/api/autorotate/demo.ts:6`
- `apps/web/api/autorotate/engine.ts:206`

### AR-04 — Stored admin credentials fall back to a key published in this repo

With `AUTOROTATE_ENC_KEY` unset, `getKey()` derives the AES-256-GCM key from the
literal `"autorotate-demo-passphrase"` with a fixed salt — both in a public repo.
`lib/env.ts` validates `APP_ID`, `APP_SECRET` and `DATABASE_URL` in production
but never `AUTOROTATE_ENC_KEY`, so the server boots on the default.

The protected values are connector admin credentials — by design more
privileged than the secrets being rotated.  Add `AUTOROTATE_ENC_KEY` to the
required set, and treat key rotation as a re-encryption migration (see AR-02
for why a decryption failure is not benign here).

- `apps/web/api/autorotate/crypto.ts:14`, `:15`
- `apps/web/api/lib/env.ts:11`

### AR-05 — Android rotation is fabricated, and a background job runs it every six hours

`SecretStore.rotateSecret()` generates a random UUID substring as the new
"fingerprint," never touches the stored credential, contacts no provider, and
writes no target.  It appends a run with `status = "completed"` and the detail
string `"Pipeline LOCK·ROTATE·PUSH·VERIFY·COMMIT·AUDIT executed successfully
on-device."` — a manufactured audit record asserting a pipeline that never ran.

`rotateAllDue()` ignores due dates and maps over *every* secret, and
`AutorotateApp` schedules it on a 6-hour `PeriodicWorkRequest`.

This is structural: `okhttp` is declared with **zero call sites**, and the app
contains no connectors, no Infisical client, and no HTTP code at all.
`TargetBinding` is a data class nothing consumes.  Until a real engine exists,
delete `rotateSecret` and the worker, and ship the app as the read-only
inventory viewer it actually is.

- `android/app/src/main/java/codes/autorotate/data/SecretStore.kt:45`, `:71`, `:80`
- `android/app/src/main/java/codes/autorotate/AutorotateApp.kt:24`

## High

### AR-06 — Web engine commits with zero targets; the Swift fix was never ported

Commit `f13ac35` (PR #17) fixed exactly this in `AutorotateCore`: programmatic
connectors mint and often deactivate the provider credential during ROTATE,
so committing with nowhere to deliver kills the old key and discards the new
one.  The TypeScript engine still treats an empty target list as success.

*Rotate Now* on a web secret with no enabled targets revokes the live AWS or
Stripe key, throws the replacement away, marks the record `healthy` at
`version + 1`, and appends `rotation.committed`.

- `apps/web/api/autorotate/engine.ts:463` vs `RotationEngine.swift:190`

### AR-07 — The audit chain races itself and cannot be repaired

`appendAudit` selects the last `entryHash`, then inserts — no transaction, no
uniqueness constraint on `prevHash`.  The 60s scheduler tick and any web
action are genuinely concurrent, so two appends can take the same predecessor.
From then on `verifyChain` returns `valid: false` permanently, because the
invariant correctly forbids rewriting history.

Also: entry hashes truncate to 16 hex (64 bits), and `audit.verifyChain` loads
the whole table unbounded on an unauthenticated endpoint.

- `apps/web/api/autorotate/engine.ts:138`, `:128`, `:165`
- `apps/web/api/routers/autorotate.ts:791`

### AR-08 — The Apple audit log is not hash-chained at all

`AuditEntry` has no `prevHash`/`entryHash`.  Append-only is enforced only by a
doc comment on the `AuditStore` protocol.  AGENTS.md invariant 2 requires
"append-only **and** hash-chained," and the README sells tamper-evidence —
both hold for the web app only.  Lift `canonicalEntry`/`computeEntryHash` into
Core so both platforms chain identically.

- `apple/AutorotateCore/Sources/AutorotateCore/Models.swift:266`
- `apple/AutorotateCore/Sources/AutorotateCore/Stores.swift:47`

### AR-09 — Unauthenticated SSRF, and stored webhook URLs handed to any caller

`workspace.testAlert` POSTs to whatever URL is stored; `targets.upsert`
accepts any `z.string().url()` with an arbitrary header map.  Nothing
restricts the scheme or blocks loopback, link-local (`169.254.169.254`) or
RFC-1918 destinations.  SECURITY.md states webhook targets must use HTTPS; no
code enforces it, so an `http://` target with `includeValue: true` ships
rotated secrets in cleartext.  `workspace.getAlerts` returns the raw Slack and
Discord webhook URLs — themselves credentials — to any caller.

- `apps/web/contracts/autorotate.ts:114`
- `apps/web/api/routers/autorotate.ts:892`, `:857`

### AR-10 — The AWS IAM connector discards the API response and returns an invented key

`rotateAwsIam` POSTs `Action=CreateAccessKey` with no SigV4 signature ("SigV4
signing elided here"), so it always fails auth — the only reason it is not
actively destructive.  On its success path it parses `AccessKeyId`, ignores
it, and returns a locally generated `AKIA…` string.  If signing were added
without fixing the return, it would create a real access key, discard it, and
push a value that authenticates to nothing.

Either implement SigV4 and return the real `SecretAccessKey`, or reclassify
AWS as `update_only`.  Shipping it as `programmatic` in the registry and the
published capability matrix overstates what the product does.

- `apps/web/api/autorotate/connectors.ts:82`, `:100`, `:529`

### AR-11 — VERIFY proves delivery, never that the new credential works

Both engines read back what they just wrote and compare it to itself.  No path
ever authenticates the new credential against its provider, so a rotation that
delivers a dead, malformed or fabricated key is indistinguishable from a
healthy one.  This is the amplifier underneath AR-02 and AR-10.  A post-commit
liveness probe reusing the existing `testConnection` shapes would catch all
three classes at once.

- `apps/web/api/autorotate/engine.ts:256`, `RotationEngine.swift:432`
- `apps/web/api/autorotate/connectors.ts:586` (exists, never called after COMMIT)

### AR-12 — macOS Keychain writes land in the legacy keychain

`kSecUseDataProtectionKeychain` appears nowhere in the repo.  On macOS a
`kSecClassGenericPassword` item without it goes to the legacy file-based
keychain, which ignores `kSecAttrAccessible` and treats access groups
differently from the data-protection keychain iOS uses.

Three documented behaviours therefore fail on macOS: the shared
`codes.autorotate.shared` group (architecture.md §5), `kSecAttrAccessible-
AfterFirstUnlock` for unattended scheduled rotation, and iCloud Keychain sync.
Setting the flag fixes all three — but it is a storage migration for existing
installs, not a one-line change.

- `apple/AutorotateCore/Sources/AutorotateCore/KeychainManager.swift:135`

### AR-13 — Android release builds are debug-signed and unminified

*See AR-33: this is no longer hypothetical — the debug-signed artifact is now
committed to the repository, which is why AR-33 is rated critical.*

`signingConfig = signingConfigs.getByName("debug")` and
`isMinifyEnabled = false` on the `release` build type.  Debug-signed artifacts
cannot go to Play, and the debug keystore password is a published constant.
R8 is off, so ProGuard files are listed but inert.

- `android/app/build.gradle.kts:23`, `:24`

### AR-14 — Android biometrics is a screen, not a lock

`MasterKey.Builder` omits `setUserAuthenticationRequired(true)`, so the
Keystore key backing `EncryptedSharedPreferences` is not bound to
authentication — stored credentials decrypt whenever the process runs.
`BiometricPrompt` only decides whether a composable renders.

`onError` is an empty comment, so a failed or cancelled prompt strands the
user on "Awaiting Biometric Authentication…" with no retry.  No window sets
`FLAG_SECURE`, so secret names, fingerprints and history appear in screenshots
and the recents thumbnail.

- `android/…/data/EncryptedStorage.kt:11`, `MainActivity.kt:44`

### AR-15 — Tests never run in CI, and the pipeline has no test at all

The `web` job runs `npm ci`, `npm run check`, `npm run build` — never
`npm test` or `npm run lint`.  The 22 vitest tests pass locally but nothing on
a PR would notice if they stopped.

Coverage is the bigger gap: every test targets a pure helper.  `rotateSecret`
— the function that revokes and replaces live credentials — has no test, which
is why AR-02, AR-03 and AR-06 all survive a green pipeline.  Android has zero
test files despite declaring JUnit and Espresso.  The Apple job is the model:
it actually runs `swift test`.

- `.github/workflows/ci.yml:30`

## Design & front-end

The hand-built layer is the strongest visual work in the repo: a disciplined
token set, a single `spin` accent kept separate from semantic
`warn`/`danger`/`info`, a named radius scale, a `.tnum` tabular-numerals rule,
and real information design in the command palette, run stepper and audit
chain strip.  Its problems come from a second system underneath it.

### AR-24 — Two colour systems disagree about the same token

Tailwind defines `ink-secondary: #9AA5B8` — **8.0:1** on the `#07090D` ground,
comfortably AA.  The CSS variable annotated as that same colour,
`--muted-foreground: 218 15% 48%`, resolves to `#68768D` — **4.33:1**, below
the 4.5:1 AA threshold.  Every shadcn-derived control renders secondary text
below AA while hand-built components beside them pass.

- `apps/web/src/index.css:20` vs `apps/web/tailwind.config.js:15`

### AR-25 — `text-ink-muted` fails AA and is used 259 times

`#5C6679` measures **3.45:1** and carries labels, table meta and helper copy
across `src/`.  `text-ink-faint` (**~1.9:1**, 25 uses) is below even the 3:1
non-text threshold.  Lighten `ink-muted` to roughly `#7C8698`, correct the
`--muted-foreground` HSL to match its own comment, and reserve `ink-faint`
for separators.

### AR-26 — The console has no mobile layout

`AppShell`'s sidebar is `fixed inset-y-0 w-60` with `ml-60` on main and **no
responsive modifier anywhere**.  Below ~700px the sidebar covers the content.
The marketing `Navbar` has a proper mobile menu, so the omission is specific
to the console — on a product whose landing page sells three companions.

### AR-27 — Chrome that looks operable and isn't

The workspace switcher ("Acme Corp"), Settings, the notification bell, and the
primary **Rotate now** topbar button all have no handler.  The "macOS linked"
pill and "production" chip are hardcoded; the avatar still reads `TS`.  In this
product a *Rotate now* button that silently does nothing is worse than no
button.

### AR-28 — The sidebar lists `/runs` twice

"Activity" (Overview) and "Rotation Runs" (Records) share a route, and active
state is `location.pathname === item.href`, so both highlight at once.

### AR-29 — `docs/design.md` is cited six times and does not exist

Referenced as the source of truth for the palette and type scale in
`tailwind.config.js` and `index.css`.

### AR-31 — No route-level code splitting

Main chunk is **1.21 MB** (347 kB gzip); every marketing visitor downloads the
entire console.  The three.js gyroscope is correctly split at 895 kB but still
loads on the landing page.

## Medium

### AR-16 — Failure alerts are configurable but never sent

`memoryAlertConfig` is read only by `getAlerts`, `updateAlerts` and
`testAlert`; the rotation engine never consults it.  No alert has ever fired
outside the Test button.  It is also a module-level global: unpersisted, lost
on restart, shared across every caller and replica.

- `apps/web/api/routers/autorotate.ts:848`

### AR-17 — `.env` import creates records that look rotated but hold nothing

`secrets.importBatch` posts the pasted plaintext, fingerprints it, and drops
the value — no target delivery — while setting `lastRotatedAt = now`.  The
modal says values "will be held in memory for target delivery," which the code
does not do.  Auto-created connectors carry `status: "connected"` with no
credentials — the precondition for AR-02.

- `apps/web/api/routers/autorotate.ts:400`, `:410`
- `apps/web/src/components/secrets/EnvImportModal.tsx:378`

### AR-18 — Fingerprints are different lengths on each platform

Web keeps 16 hex characters; Apple keeps 8; architecture.md §6 and the schema
comments specify 8.  Cross-platform drift comparison mismatches by
construction, and the web app deviates from its own spec.

- `apps/web/api/autorotate/crypto.ts:71` vs `Fingerprint.swift:17`

### AR-19 — Locks and the scheduler are per-process

The rotation lock is a module-scope `Set<number>` and `startScheduler()` runs
at import time.  Two replicas each hold their own lock set and each tick every
60s, so the same secret can rotate twice concurrently.  The scheduler also
starts under `vite dev`, so a developer pointed at a shared database rotates
production secrets from their laptop.

- `apps/web/api/autorotate/engine.ts:47`, `apps/web/api/boot.ts:11`

### AR-20 — QR pairing cannot succeed

Server emits `{version, appName, baseUrl, environment, timestamp}`; Android's
`QRPairingPayload` expects `{service, domain, workspaceId, environment,
endpoint, pairingToken}`.  Only `environment` overlaps, and the server never
emits a `pairingToken`.  The payload also hardcodes
`baseUrl: "https://mac.jays.services"`, putting a fleet infrastructure
hostname into a public repo — which AGENTS.md's private-infrastructure rule
exists to prevent.  (`appName` was corrected to `"Autorotate"` by #63; the
hostname was not.)

- `apps/web/api/routers/autorotate.ts:908`, `android/…/model/Models.kt`

### AR-21 — No rate limiting or CORS policy; edge headers cover only the static site

**Partially addressed at `b890817`.**  #84 added `apps/web/vercel.json`, which
sets `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` and
`Permissions-Policy` at the Vercel edge.  That is a real improvement for the
static site.

What it does not cover: there is still no CSP and no HSTS; the headers are
Vercel edge rules, so they do not apply to the Hono/Node server that serves
`/api/trpc/*` under `npm start`; and `boot.ts` still mounts one global
`bodyLimit` of 50 MB with no rate limiter and no CORS configuration.  With
AR-01, the unauthenticated `audit.verifyChain` full-table scan plus 50 MB
bodies remains a straightforward DoS path.

`vercel.json` also declares `framework: vite` with no function or rewrite
entry for `/api/*`, so it is worth confirming the tRPC backend is actually
deployed on that host rather than 404ing.

- `apps/web/api/boot.ts:15`
- `apps/web/vercel.json` (added by #84)

### AR-22 / AR-23 — Documented components that do not exist

`apps/agent/autorotate-agent.py` is three lines printing "Download
autorotate-agent.py from the Autorotate Devices screen."  There is no Devices
screen.  README lists the Mac agent as working and architecture.md §3 grades it
**✅ programmatic** — and invariant 3 declares that matrix the source of truth,
so this is an invariant violation as much as a docs bug.

SECURITY.md directs vulnerability reports to `security@autorotate.dev` —
renamed by #63 but still annotated in the file itself as "(placeholder
contact)".  On a public repo for a security product, reports go nowhere.

## Added at re-verification (`b890817`)

### AR-33 — **Critical** — A debug-signed release APK is committed to the public repo

`releases/android/Autorotate-1.0.0.apk` (14.8 MB, added by #63) is signed with
the Android debug keystore.  Confirmed by parsing the APK Signing Block
directly — v2 scheme (`0x7109871a`), one certificate:

```
subject = CN = Android Debug, O = Android, C = US
issuer  = CN = Android Debug, O = Android, C = US
notBefore = Aug 14 20:40:09 2026 GMT
notAfter  = Aug  6 20:40:09 2056 GMT
```

The debug keystore's private key ships with every Android SDK installation
under the universally published password `android`.  Anyone who downloads this
APK can therefore build a modified package that Android accepts as an update
to it, signed by the same key.  For a credential-management app distributed
from a public repository, that is a supply-chain problem, not a packaging nit.

Remove the artifact, add a real upload keystore held outside the repo (CI
secret or local keychain), and publish releases through GitHub Releases rather
than tracked files.  Treat the current 1.0.0 APK as compromised for
distribution purposes — its signing identity is public by construction.

- `releases/android/Autorotate-1.0.0.apk`
- `android/app/build.gradle.kts:24` (the config that produced it — AR-13)

### AR-34 — **High** — A development provisioning profile with a hardware UDID is committed

Mac **Team Provisioning Profile** — a development profile, not distribution.
Decoded, it carries:

|---|---|
| Name | `Mac Team Provisioning Profile: com.autorotate.macos` |
| TeamName | Jay Wedgeworth, LLC |
| TeamIdentifier | `CC8UTF7ATG` |
| ProvisionedDevices | **1 device UDID** (`00008142…`) |
| DeveloperCertificates | 2 embedded certificates |
| Expires | 2027-08-24 |

AGENTS.md's private-infrastructure rule explicitly forbids committing hardware
serials to this public repository, and a provisioned-device UDID is exactly
that.  To be precise about severity: the profile contains **public**
certificates, not private keys, so this is a disclosure of the team identity
and one machine identifier — not a signing-key compromise.

`gitleaks` passes because it does not decode binary CMS payloads, so this class
of leak will not be caught by the existing gate.

The archive's app `Info.plist` carries the canonical `codes.autorotate.macos`
while the profile is named for `com.autorotate.macos`, so the committed archive
also predates the bundle-ID canonicalization in #83.

## What's genuinely good

- **AutorotateCore is real engineering.**  The engine is an `actor` with
  per-secret locks, every dependency injected through a `Dependencies` struct,
  errors sanitized and truncated before reaching run history, and a
  required/optional target distinction the web model lacks entirely.
- **The no-target guard (`f13ac35`) shows real diagnostic depth.**  Recognizing
  that a mint-and-revoke connector plus an empty target list equals an
  unrecoverable outage is not an obvious bug to find.  It shipped with tests.
- **Keychain handling is correct in the details that usually go wrong:**
  `kSecAttrSynchronizableAny` on read/update/delete, `kSecAttrAccessible`
  treated as write-time-only and kept out of search queries, and a graceful
  fallback on `errSecMissingEntitlement`.
- **The file-target sandbox is right.**  `resolveSandboxPath` resolves then
  verifies the prefix with a separator check, and writes are atomic via
  tmp-plus-rename.
- **Canary and dry-run guards are thoughtful fixes to real hazards.**  Both
  carry tests and explanatory comments.
- **The `fsp: 3` comment on `auditLog`** records someone finding and fixing a
  genuine millisecond-precision chain-verification bug.
- **macOS entitlements are minimal and correct:** sandboxed, user-selected
  read/write with app-scoped bookmarks, network client only, hardened runtime.
- **The architecture document is unusually good** — specific enough to audit
  against, which is what made most of this review possible.

## Fix order

Sequenced by risk retired per unit of work.

1. **Pull the published artifacts.**  `git rm --cached` `releases/` and
   `build/`, add `build/` to `.gitignore`, and stand up a real Android upload
   keystore outside the repo.  History still carries them, so treat the 1.0.0
   APK's signing identity and the provisioned UDID as public.

   localhost behind a tunnel — until AR-01 has a real answer.
   *(AR-01, AR-09, AR-21)*
3. **Make the engine fail closed:** throw when a connector has no config
   instead of returning a demo value; require `AUTOROTATE_ENC_KEY` and
   `AUTOROTATE_DEMO` explicitly in production; refuse to commit with zero enabled
   targets.  *(AR-02, AR-03, AR-04, AR-06)*

   inventory viewer it is, and stop writing fabricated audit history.

   first pipeline tests — no-target commit, missing-config rotate, demo-mode
