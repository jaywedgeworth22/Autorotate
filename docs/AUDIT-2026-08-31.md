## Verdict

The August 26 critical story is **closed on HEAD**: session auth wraps tRPC, demo is opt-in, missing connector config fails closed, the audit append is lock-pinned, webhooks go through `safeFetch`, AWS is update-only on web, liveness gates commit, Android no longer fabricates rotation runs, and Apple Core hash-chains audit entries.

What remains is a **second generation of fail-open and honesty bugs**, plus a fleet-wide product-policy miss: every surface is **dark-only**.

Three findings invert the product promise again:

1. **Web will mint (and often revoke) a live provider credential when the only target is Keychain**, then report PUSH success while discarding the new value.  Same class as AR-06, different target kind.
2. **The Kubernetes connector creates a real ServiceAccount then returns `randomBytes(48)`** — invented credential, same class as the old AWS mint.
3. **Android first launch seeds a fake AWS/Stripe/GitHub inventory** with fabricated fingerprints.  Rotation fabrication is gone; inventory fabrication is not.

A fourth class is policy, not crash: **web, iOS, macOS, and Android all boot dark with no Light | Dark | System control**, against the 2026-08-10 light-default ruling.

## P0 — Fix before treating rotation as real

### AR31-01 — Web Keychain-only targets satisfy mint eligibility and discard the new secret

**Module:** web backend · `AR31-WB-01`
**Evidence:** `apps/web/api/autorotate/engine.ts` `canMintForTargets` (count > 0 only); PUSH `case "keychain"` returns `delegated to companion app` with no delivery; VERIFY skips real read-back.

A programmatic connector **revokes the old provider credential during ROTATE**.  If the only enabled target is Keychain, the new plaintext exists only in process memory, then is discarded, while the run can still commit healthy.  Same outage class as AR-06.

**Fix:** Treat web-side `keychain` as non-delivering for mint eligibility.  Require at least one of Infisical / file / webhook with real config, or a companion ack.

### AR31-02 — Kubernetes connector invents a token after creating a ServiceAccount

**Module:** web backend · `AR31-WB-02` / `AR31-SEC-05`
**Evidence:** `apps/web/api/autorotate/connectors.ts` `rotateKubernetes` POSTs a real SA create, then `return randomBytes(48).toString("base64url")`.  Architecture lists Kubernetes as a **target**, not a programmatic source.

PUSH/VERIFY can succeed; liveness is null for kubernetes; COMMIT can mark healthy with a worthless value.  Repeat of the old AWS invent-mint.

**Fix:** Reclassify as `update_only`, or return a real cluster token.  Align `docs/architecture.md` in the same commit.

### AR31-03 — Android first launch seeds a fake secret inventory

**Module:** android · `AR31-AND-03`
**Evidence:** `EncryptedStorage.getSecrets()` returns `defaultSecrets()` (AWS / Stripe / GitHub, fabricated 8-hex fingerprints) when `secrets_list` is missing.

This is not the deleted fabricated *rotation*.  It is a fabricated *inventory*.  Combined with biometrics default-off, first launch shows three “managed credentials” that were never imported.

**Fix:** Return `emptyList()` and an empty-state CTA.

### AR31-04 — Core audit append is fail-open; AUDIT step always reports succeeded

**Module:** AutorotateCore · `AR31-CORE-01`
**Evidence:** `RotationEngine.audit` / `persist` use `try?`.  The AUDIT step is hard-coded `.succeeded` even when nothing was written.

A rotation can commit targets while the append-only hash chain silently skips the terminal entry (AGENTS.md invariant 2).

**Fix:** Make append throwing; mark AUDIT `.failed` and the run `.partial` if persist fails.  Test with a throwing `AuditStore`.

### AR31-05 — Pairing QR sends workspace `baseUrl` to `api.qrserver.com`

**Module:** web frontend · `AR31-WF-03` / `AR31-SEC-01`
**Evidence:** `apps/web/src/components/pairing/QRCodePairingModal.tsx` encodes the pairing JSON into a third-party QR URL.

A secrets product should not leak deployment hostname/topology to a foreign CDN.

**Fix:** Generate QR client-side.  Never put pairing JSON on a foreign query string.

### AR31-06 — Provider / Infisical error bodies can land in `stepsJson`

**Module:** web backend · `AR31-WB-03` · Core cousin `AR31-CORE-04`
**Evidence:** Connector/Infisical errors splice 160–200 bytes of upstream body into `Error.message`; engine stores that in `rotationRuns.stepsJson`.  Core `sanitize` is prefix-300 of `String(describing: error)` including HTTP body excerpts.

Providers sometimes echo submitted secrets in error pages.  That is plaintext-adjacent persistence (invariant 1).

**Fix:** Persist status codes only.  Never store raw upstream bodies.

### AR31-07 — Atomic file writes can leave plaintext secret temps on disk

**Module:** Core used by macOS · `AR31-MAC-05`
**Evidence:** `FileTargets.swift` `atomicWrite` writes the updated secret file to `.<name>.autorotate-<UUID>.tmp` with `atomically: false`, then rename.  Kill between write and rename leaves a plaintext temp.  New files may be created with default umask (often world-readable).

**Fix:** Open the temp with `0600` before write; `defer` unlink; prefer coordinated replace.

### AR31-08 — Web `targets.configJson` still stores secrets in plaintext JSON

**Module:** web backend · known board `b052d650` · `AR31-WB-04`
**Evidence:** `db/schema.ts` `configJson: json(...)`.  API masking exists; DB/backups/replicas still hold Infisical `clientSecret` and webhook auth headers.

**Fix:** Encrypt with the same envelope as `connectors.configEnc`.  Migrate existing rows.

## Viewport / native-size findings (condensed)

**Phone 320–430.** Marketing stepper overflows.  Console tables require horizontal scroll (Runs 1020px, Audit 900px).  Targets clip.  Icon buttons ~28px.  No `safe-area-inset`.  Secrets table-default.  Android is a stretched phone layout with no `WindowSizeClass`.  iOS is usable but Dynamic Type / landscape are thin.

**Tablet 768.** `useIsMobile` flips at 768.  AppShell drawer exists (`md`).  Data pages still render desktop tables.  Android/iOS have no two-pane.

**Laptop 1024 / 13″ Split View.** macOS window min 980pt vs Secrets split ~1020pt — layout fights the window.  Web is comfortable here.

**Desktop 1280–1440 / ultrawide.** Best-supported.  Audit mounts up to 300 DOM rows (no virtualization).  Hardcoded “Acme Corp” workspace chrome.
